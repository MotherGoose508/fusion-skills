# Connection and evidence

- Prefer a callable Fusion MCP connection. Inspect tools exposed to this session and use a supported read-only operation to establish the Fusion version if exposed, current document identity and capabilities. A registered server, open port or tool name alone does not establish access. Verify capabilities individually for timeline, parameters, edits, relationships, interference, save, and export as needed.
- In Autodesk Fusion desktop, a Python script may run through **Utilities → Add-Ins → Scripts and Add-Ins**. Generate or adapt the script for the task, then inspect its output from a real Fusion run before claiming success. Use a new document for new models and experiments. For edits, guard the target using the expected document and a component or parameter signature, and check for partial writes before reruns.
- Fusion's Python API uses internal centimetres for numeric lengths and radians for numeric angles. Pass explicit unit strings for dimension expressions where supported. Convert coordinates and measurements at API boundaries. Use the documented API for the installed version. [Autodesk units guide](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/Units_UM.htm)
- If hands-on execution is unavailable, deliver the strongest feasible handoff. Record what was inferred from the supplied files and what still requires Fusion. A screenshot can evidence visible shape but cannot prove parameter regeneration or motion.
- Record observable elapsed time, tool calls and retries if evaluating workflows or if requested. Treat a requested time or call allowance as a planning constraint. Report credits only if displayed by the host.
